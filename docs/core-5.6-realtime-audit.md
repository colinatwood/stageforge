# Core 5.6 real-time audit and overload shedding

Core 5.6 instruments each native output callback using fixed atomic counters. It records callbacks, deadline misses, consecutive misses, maximum duration, sanitized non-finite samples, input-ring pressure, optional-effect shedding and recovery transitions. The callback performs no reporting I/O; authenticated control-thread status reads the counters.

Three consecutive misses enter degraded overload; ten consecutive misses mark critical overload. Overload indication clears after 128 consecutive on-time callbacks. Effect processing continues while the runtime reports the level; it does not mutate the live chain from the callback.

`POST /api/v1/audio/overload/plan` turns bounded audit evidence and explicit effect classifications into a deterministic advisory plan. Degraded operation recommends the highest-priority eligible effect; critical operation recommends every eligible effect. Only effects marked both `optional` and `latency-preserving` are eligible. Essential effects and latency-unsafe bypasses are reported as blocked, recovery recommends restoration of effects previously bypassed by policy, and every plan states `automaticApply: false` and `physicalOutputsArmed: false`.

`EffectDelayTransaction` now wraps the native render callback: it pins a bounded configuration before graph/effect processing, preserves the existing effect-before-limiter order, processes compensation from the same bank, then releases the reader. Authenticated runtime actions can prepare, activate or roll back a generation. Only changes classified as both optional and latency-preserving pass the runtime gate, while native validation rejects unknown or duplicate effect targets and refuses to overwrite a bank still used by a callback.

Automatic overload response remains disabled. `POST /api/v1/audio/overload/prepare` requires an authority holder to acknowledge the reviewed plan, then recomputes the deterministic recommendation while holding the mutation boundary. The reviewed action and ordered effect IDs must match exactly, and each target's bypass latency must equal its active latency. A successful request only prepares the atomic generation; a separate Show-Time activation remains mandatory. Real plugin failure, timing and audible-transition behavior remain qualification work.

Every rendered sample is checked before interleaving. NaN or infinity becomes silence and increments evidence. This is a containment boundary, not a substitute for fixing the offending provider.

Core 5.7 begins ingress coverage with allocation-free MIDI counters for poll calls, bytes read, parsed or injected messages, bounded-queue drops and maximum poll duration. Core 5.8 adds per-input capture callback counts, frames, recording blocks, queue rejection, non-finite sample containment and maximum duration. NaN and infinity are replaced with silence before entering monitoring or recording queues. Core 5.9 covers the lighting show-loop handoff with accepted/rejected event counts plus drain calls, events and maximum duration. The backend plugin-host audit adds serialized request accounting, processed blocks/samples, timeout, disconnect, host-error and malformed-response evidence. Timed-out children are killed and reaped; malformed or non-finite output fails to bypass. Live host status is projected through the authenticated audit endpoint. Control-thread reads use `org.upp.core.ingress-audit/1`; ingress paths perform no reporting I/O.

The output extension remains `org.upp.core.realtime-audit/1`. Public C ABI 1.66 carries MIDI, capture and lighting status through `org.upp.core.ingress-audit/1`, and engine handshake 4.9 advertises `ingressAudit=1`. Software timing tests do not qualify any particular operating system, interface or plugin under production load.
